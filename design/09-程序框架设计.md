# 09 — 程序框架设计

## 设计目标

定义游戏的技术架构、核心类的继承体系和模块划分。本文档衔接设计文档与代码实现，为开发团队提供可直接落地的技术蓝图。

**定位：** 定于"怎么做"而非"做什么"——每个系统明确定义其 UE5 基类、继承链、关键接口和数据契约。

---

## 技术选型

| 层面 | 选型 | 理由 |
|------|------|------|
| 引擎 | **Unreal Engine 5** | 大型世界流式加载、程序化地形、C++ + Blueprint 双栈 |
| 玩法逻辑 | UE C++（核心系统）+ **Blueprint**（玩法编排） | C++ 实现性能关键路径，Blueprint 编排跨系统流程 |
| 程序化生成 | UE PCG 框架 + **自定义规则引擎** | PCG 处理地形/植被；规则引擎驱动 POI 模板组合 |
| 物理 | UE Chaos Physics | 飞船飞行、零重力环境、碰撞检测 |
| 网络 | 单机优先，后期扩展 UE Replication | 模块边界预留网络同步接口 |
| UI | UE Common UI + UMG | 跨平台输入适配 |
| 音频 | UE MetaSounds + Wwise | 程序化音频（引擎声随参数变化） |
| 存档 | 自定义序列化（二进制 + JSON 元数据） | 二进制存运行时状态，JSON 存元数据便于调试 |

### Subsystem 选型原则

| 生命周期 | 基类 | 适用系统 | 原因 |
|----------|------|----------|------|
| 跨关卡持久 | `UGameInstanceSubsystem` | 建造、宇宙、进度、资源、叙事、事件总线 | 状态不随加载/卸载而丢失 |
| 单关卡/世界 | `UWorldSubsystem` | 生存、战斗、探索、POI | 随世界加载初始化，随世界销毁清理 |

**数据流：**
```
每 1 秒:
    USurvivalManager::Tick(DeltaTime)
        → for each UVitalSignComponent in World:
            → 基于当前环境计算消耗率
                ├── IsInSealedEnvironment？ → 低消耗
                ├── IsInBreachedCompartment？ → 高消耗（急速失压）
                └── IsInHazardZone？ → 额外消耗（辐射/温度/有毒大气）
            → 更新各项指标
            → 检查阈值
                ├── O2 < 30% → FireEvent("O2Warning")
                ├── O2 < 10% → FireEvent("O2Critical")
                ├── Health <= 0 → FireEvent("PlayerDeath")
                └── Radiation > Threshold → ApplyStatusEffect(URadiationSicknessEffect)
```

## 已实现系统详情

### 电力网络系统（已实现）

采用**普通 C++ 类**（非 UObject），通过链表和信号标志实现灵活的电力传输与逻辑控制。

```
ElectricManager                          // 管理器（非 UObject，手动管理生命周期）
 ├── TSet<FElectricNode*> ElectricNodes  // 所有节点集合
 ├── FElectricNode* AddNode(...)         // 创建并注册节点
 ├── void RemoveNode(FElectricNode*)     // 移除节点
 └── void Tick()                         // 每帧驱动: Transfer() → PrepareNextPeriod()

FElectricNode                            // 电力网络节点（普通 C++ struct）
 ├── float InputPower                    // 本帧输入功率
 ├── float MaxInputPower                 // 过载保护阈值（默认 9999）
 ├── float Capacity / MaxCapacity        // 电池（缓存多余功率）
 ├── float ConsumePower                  // 自身消耗
 ├── ELESignalFlag SignalFlag            // 输出信号标志
 ├── ELESignalFlag WorkFlag              // 当前工作信号
 ├── FElectricNode* LinkedNode           // 下游节点（单向链表）
 ├── void Transfer()                     // 传输逻辑: 信号判断 → 过载检测 → 电池充放 → 传递
 └── void PrepareNextPeriod()            // 周期重置: InputPower → BeforeInput, 清除标志
```

**信号标志 (ELESignalFlag)** — 布尔逻辑路由：
```
None | NoContains | Not | Or1 | Or2 | And1 | And2 | Xor1 | Xor2
```
- 使用 `ENUM_CLASS_FLAGS` 支持位运算
- `Transfer()` 中通过 `EnumHasAllFlags`/`EnumHasAnyFlags` 判断节点是否通电
- 信号随功率沿网络传播：上游输出 → `|=` 写入下游 `WorkFlag`

**器具链表 (AAppliance)**：
```
AAppliance : AActor
 ├── InNode / OutNode (×2)            // 双通道输入输出
 ├── ParentAppliance / ChildrenAppliance  // 链表结构
 ├── TempTail                         // 遍历用临时指针
 ├── virtual IniElectricNode()        // 子类重写：创建专属电力节点
 ├── void Linked()                    // 链接到电力链
 └── void SetNoCableLink(...)         // 无线直连
```

**设计要点：**
- 非 UObject 设计适合高频 Tick（避免 GC 开销），但需注意**手动内存管理**——`AddNode` 用 `new` 分配，目前无对应的 `delete`
- 信号标志系统让电力网络支持"条件通电"——如"仅当引擎启动且武器未过热时，护盾增强器才通电"
- 链表结构支持器具串联：电源 → 反应堆 → 配电板 → 各设备
