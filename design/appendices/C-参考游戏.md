# 附录 C — 参考游戏

> 每个参考游戏都有值得借鉴的设计选择，也有值得警惕的陷阱。本表帮助在开发过程中保持清醒的参考意识。

---

## 核心参考

### Subnautica

| 值得借鉴 | 值得警惕 |
|----------|----------|
| 生物群系作为自然进度门 —— 更深=更难，但不需要锁 | 过度依赖线性故事触发来推动进度 |
| 基地建造的满足感 —— 每个新模块带来新能力 | 后期材料收集变得重复 |
| 恐怖感来自环境本身，不是跳跃惊吓 | 建造菜单的交互后期变得繁琐 |
| 扫描=进度，信息=奖励 | 缺乏自动化选项，后期建造大型基地很累 |
| "下水前要检查氧气"的紧张感 → 我们的"离开安全区前检查生命支持" | |

### No Man's Sky

| 值得借鉴 | 值得警惕 |
|----------|----------|
| 程序生成宇宙的广袤感 | 生存机制太浅（几乎是事后才想到的） |
| 基地建造的自由度和组件库丰富 | 兴趣点高度重复（看了三个星球等于看了全部） |
| 从零开始到舰队指挥的成长弧线 | 飞船定制程度不够（只有等级，没有真正的模块取舍） |
| 社区更新持续完善游戏 | 多人模式稀释了孤独感 |

### Starfield

| 值得借鉴 | 值得警惕 |
|----------|----------|
| 模块化飞船建造的深度 —— 每个零件的取舍有真正的玩法影响 | 内部布局不可控（门和梯子自动生成，经常不合理） |
| 建造验证系统（错误/警告分层）—— 清晰的约束让建造有"解谜"感 | 无蓝图/规划模式 —— 建造即付费，试错成本高 |
| 制造商差异化 —— 同一功能模块有不同风格和数值倾向，增加选择的趣味 | 改装导致手工装饰全部重置 —— 极度挫败 |
| 飞船等级系统（反应堆 A/B/C 级）—— 清晰的升级目标 | 模块不可旋转、不可翻转 —— 限制创造自由 |
| 船员技能影响飞船性能 —— 建造与 NPC 系统的联动 | 起落架承重等约束对新玩家不够直观 |

### FTL: Faster Than Light

| 值得借鉴 | 值得警惕 |
|----------|----------|
| 系统级损伤 —— 不同系统受损有不同后果，而不是统一HP | Roguelike永久死亡（与我们的建造游戏类型矛盾） |
| 决策时刻的紧张感 ——"修护盾还是修引擎？" | 战斗过于频繁（与我们"探索>战斗"的支柱矛盾） |
| 舰队追击制造时间压力 | 舰内管理过于抽象（缺乏空间感） |
| 船员各有特长，但任何船员都可以操作任何系统 | |

## 次要参考

### Space Engineers

| 值得借鉴 | 值得警惕 |
|----------|----------|
| 工程深度 —— 飞船不只是外观，内部系统有真正的物理关系 | 学习曲线极陡峭 —— 门槛太高 |
| 破坏模型的物理性 —— 船体按板块真实损坏 | 物理引擎抖动问题严重影响体验 |
| 模块之间真实连接（管道、电线） | 优化差 —— 大型建设物导致严重掉帧 |
| 蓝图和投影建造系统 | 几乎没有生存压力和探索内容 |

### Raft

| 值得借鉴 | 值得警惕 |
|----------|----------|
| 基地逐步从木筏成长为巡洋舰的满足感 | 内容范围局限 —— 一个海洋主题撑完全程 |
| "资源漂过来"的被动采集设计 → 可借鉴为"太空中漂过的残骸" | 后期建造物变得过大但功能不增长 |
| 鲨鱼作为恒常威胁制造基础级紧张 → 类似我们的"太空环境威胁" | 战斗系统深度有限 |
| 钩爪收集远处的资源 —— 直观且有趣 | 故事线推进方式（按坐标找下一个岛）过于公式化 |

### The Long Dark

| 值得借鉴 | 值得警惕 |
|----------|----------|
| 生存紧张感 —— 知道暴风雪要来，你必须规划下一步 | 没有建造系统 —— 与我们"建造即进度"支柱矛盾 |
| 不靠怪物，靠环境制造恐惧 | 步行模拟 —— 缺乏我们的探索自由度（飞船vs步行） |
| 每一个篝火都是"我做到了"的里程碑 | 死亡代价过于严苛（永久死亡） |
| 信息不透明 —— 你永远不确定狼群在哪，保持紧张 | 资源刷新机制导致长期存活无意义 |

## 影视/文学参考

| 作品 | 借鉴元素 |
|------|----------|
| 《星际穿越》(Interstellar) | 时间的相对性、探索与牺牲的尺度感 |
| 《萤火虫》(Firefly) | 一艘小飞船就是全部的家，在星系边缘挣扎求生 |
| 《浩瀚苍穹》(The Expanse) | 硬科幻的真空物理、派系政治、飞船作为"角色" |
| 《异形》(Alien) 系列 | 深空的恐怖感、废弃飞船的环境叙事 |
| 《基地》(Foundation) | 文明兴衰的尺度、科技失传的悲剧 |
| 《无人深空》美术 | 色彩的孤独感、科幻封面式视觉风格 |

## 关键设计教训（跨作品总结）

1. **广度 vs 深度** —— 宁可只有 20 个有意义的星系，不要 2000 亿个都一样的。
2. **生存压力要有节奏** —— 持续高压是折磨，没有压力是无趣。呼吸式的紧张-放松循环是关键。
3. **建造需要功能回报** —— 玩家不是为了好看而建造，是为了获得新能力。纯装饰部件是锦上添花，不能是核心。
4. **不要让玩家查 Wiki** —— 配方树可以深，但配方逻辑要直观（铁→铁锭→框架→模块，不是"三根羽毛+一个轮胎=火箭"）。
5. **孤独感是价值不是缺陷** —— 太空游戏最独特的体验就是孤独。不要急着填满 NPC 和任务来"解决"孤独，而是让孤独成为有意义的情绪。
6. **操作手感 > 数值深度** —— 飞行的手感、采矿的反馈、建造的拖放手感，这些比任何数值平衡都重要。
