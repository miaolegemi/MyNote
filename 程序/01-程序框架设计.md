# 09 — 程序框架设计

## 设计目标

定义游戏的技术架构、核心类的继承体系和模块划分。本文档衔接设计文档与代码实现，为开发团队提供可直接落地的技术蓝图。

**定位：** 定于"怎么做"而非"做什么"——每个系统明确定义其 UE5 基类、继承链、关键接口和数据契约。

> 本文档为技术架构总览。规划中系统的详细设计见 [[02-核心系统详细设计]]，已实现系统的代码级描述见 [[03-已实现系统详情]]。

## 技术选型

| 层面 | 选型 | 理由 |
|------|------|------|
| 引擎 | **Unreal Engine 5** | 大型世界流式加载、程序化地形、C++ + Blueprint 双栈 |
| 玩法逻辑 | UE C++（核心系统）+ **Blueprint**（玩法编排） | C++ 实现性能关键路径，Blueprint 编排跨系统流程 |
| 伤害/效果 | **Gameplay Ability System (GAS)** | 角色伤害、环境伤害、状态效果、Buff/Debuff 统一使用 GAS 的 AttributeSet + GameplayEffect + GameplayAbility |
| 程序化生成 | UE PCG 框架 + **自定义规则引擎** | PCG 处理地形/植被；规则引擎驱动 POI 模板组合 |
| 物理 | UE Chaos Physics | 飞船飞行、零重力环境、碰撞检测 |
| 网络 | 单机优先，后期扩展 UE Replication | 模块边界预留网络同步接口（GAS 原生支持网络同步） |
| UI | UE Common UI + UMG | 跨平台输入适配 |
| 音频 | UE MetaSounds + Wwise | 程序化音频（引擎声随参数变化） |
| 存档 | 自定义序列化（二进制 + JSON 元数据） | 二进制存运行时状态，JSON 存元数据便于调试 |

**Build.cs 依赖模块（公有）：** `Core`, `CoreUObject`, `Engine`, `InputCore`, `EnhancedInput`, `UMG`, `StructUtils`, `GameplayAbilities`, `GameplayTags`, `GameplayTasks`
**Build.cs 依赖模块（私有）：** `Slate`, `SlateCore`

### Subsystem 选型原则

| 生命周期 | 基类 | 适用系统 | 原因 |
|----------|------|----------|------|
| 跨关卡持久 | `UGameInstanceSubsystem` | 建造、宇宙、进度、资源、叙事、事件总线 | 状态不随加载/卸载而丢失 |
| 单关卡/世界 | `UWorldSubsystem` | 生存、战斗、探索、POI | 随世界加载初始化，随世界销毁清理 |

## 事件总线

系统间唯一合法的跨系统通信方式。

```cpp
UCLASS()
class UEventBus : public UGameInstanceSubsystem {
public:
    DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnModulePlaced, const FModulePlacedEvent&, Event);
    DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnO2Critical, const FO2CriticalEvent&, Event);
    DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnTechUnlocked, const FTechUnlockedEvent&, Event);
    // ... 其余事件
    
    void Subscribe(FName EventName, UObject* Subscriber, FName HandlerFunc);
    void Unsubscribe(FName EventName, UObject* Subscriber);
    void Publish(FName EventName, const FEventData& Data);
    
private:
    TMap<FName, FOrderedHandlerList> HandlerMap;  // 按优先级排序
    TQueue<FDeferredEvent> DeferredQueue;          // 异步延迟事件
};
```

### 核心事件

| 事件名 | 发送方 | 接收方 | 关键数据 |
|--------|--------|--------|----------|
| `ModulePlaced` | UBuildManager | Progression, Survival | ShipID, ModuleDef, Position |
| `ModuleRemoved` | UBuildManager | Survival, ResourceEconomy | ShipID, ModuleID, RefundMaterials |
| `O2Critical` | USurvivalManager | HUD, Combat | PawnID, O2Percent |
| `ShipDestroyed` | UCombatManager | Progression, Narrative, Survival | ShipID, DestroyerID, Location |
| `PlayerDied` | USurvivalManager | Save, Progression | DeathContext |
| `TechUnlocked` | UProgressionManager | Build, ResourceEconomy | TechID, NewSchematics[] |
| `SystemDiscovered` | UExplorationManager | Narrative, Progression | SystemID, DiscoveryData |
| `ScanCompleted` | UScannerSystem | Progression, ResourceEconomy | Target, DiscoveredData |
| `ReputationChanged` | UFactionManager | Combat, ResourceEconomy | FactionID, OldValue, NewValue |
| `BuildValidationFailed` | UBuildValidator | HUD | ShipID, Errors[], Warnings[] |
| `ProgressionNodeReached` | UProgressionManager | Narrative, HUD | NodeID, UnlockedAbility |

UCLASS(BlueprintType)
class UModuleDef : public UDataAsset {
    // 标识
    FName ModuleID;
    FText DisplayName;

    EConnectionType Type;        // Passage/Structural/Weapon/Pipe

## 存档策略

```
SaveFile/
├── header.json              // 存档版本、时间戳、玩家名
├── player.dat               // 玩家运行时数据（二进制）
├── universe.dat             // 宇宙状态：已生成星系、已发现 POI
├── ships/                   // 每艘飞船独立文件
│   ├── ship_001.dat
│   └── ship_002.dat
├── bases/                   // 每个基地独立文件
│   ├── base_001.dat
│   └── base_002.dat
├── progression.dat          // 科技树、设计图、里程碑状态
├── narrative.dat            // 叙事线索、派系关系
└── starmap.dat              // 星图探索状态
```

**分层优势：** 建造数据独立 → 支持设计图导出/分享；死亡不回滚建造 → 只丢失出航收获；按需加载而非全量。
